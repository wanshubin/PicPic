## 一、稳定性 & 异常容错

1. RAW 解码各类失败场景

- 场景：文件损坏、截断、IO 读取失败、拜耳模式识别失败
- 需要做：友好弹窗提示，日志输出详细原因；**不崩溃、不覆盖当前编辑会话**；拜耳识别失败自动禁用拜耳域相关校正（串扰补偿、拜耳域 CCM），继续正常渲染。

2. 内存耗尽处理

- 场景：高像素大图渲染，内存分配失败
- 需要做：终止本次渲染，状态栏 + 日志报错；释放已分配内存，程序继续可用，不能直接崩溃。

3. 工程与校准配置文件容错

- JSON 文件物理损坏：拒绝加载，弹窗告警，**保持当前编辑状态不变，不把当前参数冲掉**。
- 配置文件版本高于程序版本：弹出警告，允许继续加载，缺失字段回退默认值。
- `.camcal` / `.lenscal` 部分字段缺失：只补缺失项，已有合法参数保留，不整体重置。
- 工程保存使用**原子写入**：先写临时文件，全部写完再替换正式文件，防止程序中途退出产生半损坏 json。

4. 可选依赖降级处理（lensfun）

- 场景：编译关闭 lensfun，或者运行时 lensfun 数据库丢失
- 需要做：镜头校正整套 UI 置灰不可操作；其余全部功能不受影响；日志写明降级原因。

5. CCM 矩阵非法运行时保护

- 场景：矩阵 NaN、行列式异常
- 需要做：渲染环节回退原厂相机矩阵进行渲染；UI 层持续保留用户输入，标红警告，**不自动改写用户正在编辑的矩阵内容**。

## 二、构建、打包、许可部署

1. CRT 混合检测

- 需要做：CMake 增加检测逻辑，如果 vcpkg 三元组与编译选项出现 `/MD` `/MT` 混用，直接报错终止构建，输出明确提示。

2. 编译开关控制 lensfun

- 需要做：增加编译选项 `BUILD_WITH_LENSFUN`，可开启 / 关闭镜头校正模块；关闭时相关 UI 自动置灰。

3. 资源自动部署

- 需要做：CMake 构建后自动复制 lensfun version_1 数据库目录到输出目录。

4. 静态编译约束

- 需要做：文档写明静态 Qt 必须内置平台插件、图像插件；否则静态 exe 会出现窗口、图片解码异常。

5. 许可文件随包输出

- 需要做：发布产物必须附带 GPLv3 许可证、NOTICE 文件，写明所有第三方库及对应许可证。

6. 输出构建说明

- 需要整理两套完整构建命令：开发调试（动态）、release 静态单 exe，写明 vcpkg 三元组、依赖获取步骤。

## 三、交互、预览调度、用户体验补齐

1. 渲染任务过期丢弃

- 场景：滑块快速拖动，大量预览任务排队堆积
- 需要做：每个渲染请求附带代次编号；新请求到来，标记旧任务为过期；旧任务完成后检测代次，过期结果直接丢弃，不更新画布，避免 UI 卡顿。

2. 预览视图逻辑严格隔离

- 需要做：「观感预览 / 线性标定视图」只改变渲染预览分支，**绝不修改 EditContext 用户参数；导出流程永远不走预览层的自动曝光、S 曲线**。管线内部预览影调属于预览分支附加逻辑，导出分支完全跳过。

3. 1:1 原始像素视图

- 需要做：关闭拜耳域降采样，使用原图分辨率渲染；UI 给出提示，告知用户 1:1 模式预览性能会下降属于预期行为。

4. 镜头配置加载锁定语义实现与提示

- 规则：用户手动修改滑块，该模块标记为已锁定；**即使点重置按钮回到默认值，锁定标记依然保留**；已锁定模块不会被 `.lenscal` 覆盖。
- 需要做：UI 面板增加小字说明该行为；想要完整套用镜头配置，需要重新打开 RAW 重置全部参数再加载配置。

5. 分组重置功能

- 需要做：传感器、CCM 矩阵、彩边校正、光影等大面板支持分组一键重置，而不是只能单个控件重置。

6. 直方图增强

- 需要做：增加高光、阴影裁切检测；可开关画布闪烁标记，在预览图上高亮显示裁切像素。

7. 参数快照持久化

- 当前快照只存在内存；需要做：快照存入 `.rawedit.json` 工程文件，打开工程自动恢复快照列表。

8. 导出元数据与格式扩展

- 需要做：导出图片复制 RAW 基础 EXIF 信息（相机、镜头、ISO、曝光）；增加 16bit EXR HDR 导出格式。

9. 日志易用性

- 需要做：日志面板增加「复制全部日志」按钮，方便用户提交 bug 反馈。

10. 渲染进度与取消

- 需要做：状态栏展示渲染进度百分比；渲染任务支持协作式取消，每个管线阶段做取消标志检查。

## 四、新增功能能力（基于现有底层，不改动核心管线顺序）

> 
> 前提：不改动现有管线执行顺序，不触碰白平衡位置等架构性变更

1. 色卡 CCM 求解 UI

- 底层已有求解函数；需要做 UI 交互：导入色卡 RAW，框选色卡区域，识别色块，求解 3×3 CCM 矩阵；预览结果，可保存输出 `.camcal`。

2. 校准档案简易管理器

- 需要做：UI 浏览本机的 `.camcal` 文件，支持重命名、删除基础管理操作。

3. 画布 OpenGL 加速绘制

- 需要做：渲染输出图像上传 GPU 纹理，OpenGL 绘制画布；减少 CPU‑GPU 拷贝，大窗口拖动更流畅；保留原有 CPU 绘制作为备选兜底。

4. 基础批量导出队列

- 需要做：UI 队列，多张 RAW 使用各自独立工程参数批量导出；**不做统一批量编辑**，每张图片沿用自身保存的参数。

5. 命令行导出工具

- 需要做：复用 core 核心库，做无 GUI 命令行程序，实现 RAW 转图片导出，可供脚本调用。

6. 完整 3D‑LUT 交互 UI

- 底层管线已经预留接口；需要做 UI：加载`.cube`，调节混合强度预览；支持把当前调色结果导出 cube LUT。

7. DNG 兼容性加强

- 需要做：改善线性 DNG、自定义拜耳 pattern DNG 解析与处理。

## 五、高级校正能力（属于后期，改动偏大）

> 
> 依旧不改动现有管线主顺序

1. 暗场帧校正：支持导入暗场 RAW 帧，做逐像素暗噪声补偿。
2. 平场帧校正：导入平场帧，补偿镜头渐晕、传感器像素响应不均。
3. 蒙版基础数据模型搭建：只搭建数据结构与存储，暂不实现复杂画笔绘制 UI。

## 六、架构高风险改动（必须独立分支，完整回归测试之后才能合并，不要混入日常开发）

> 
> 这些改动会改变管线逻辑、缓存逻辑、标定逻辑，改动后全部旧样本、工程文件都要做回归校验

1. 拜耳传感器域白平衡重构：把白平衡移到 CCM 矩阵之前；需要重构渲染缓存分层，CCM 标定流程全部更新，大量回归测试。
2. 完整 GPU 渲染后端：实现 `IRenderBackend`，绝大部分管线步骤 GPU 执行；CPU 后端继续保留用于导出、单元测试。

## 七、测试与校验要求

1. Core 无 Qt 模块编写单元测试

- 矩阵运算、XYZ‑ProPhoto 色彩转换、色温换算、PCHIP 曲线插值。
- JSON 序列化往返测试：读写工程、camcal、lenscal，校验参数读写一致性。

2. 管线快照回归测试

- 固定 RAW 输入 + 固定 EditContext，输出参考 TIFF；代码修改后比对像素误差，防止重构无意间改变成像结果。

3. 手动测试场景集合

- 多种拜耳相机 RAW 样本、高 ISO、大光比、高光光斑；
- 损坏配置文件、版本不匹配配置；
- 缺失 lensfun 数据库、关闭 lensfun 编译的情况；
- 导出校验：ICC 嵌入、位深、色彩正确性。

## 八、需要对外 / 写进注释的固有限制（代码注释、发布说明）

1. 当前白平衡运行在 ProPhotoRGB 域，不是拜耳传感器域；该调整属于高风险架构改动。
2. 只支持 RGGB/BGGR/GRBG/GBRG 标准拜耳阵列；不支持富士 X‑Trans，打开会出现严重伪色。
3. FBDD 是拜耳域算子，只能运行在 Demosaic 之前，不能放到 RGB 三通道之后。
4. 拜耳域预览降采样只能偶数倍率；奇数倍率会破坏拜耳相位，产生伪彩色。
5. 全部通道完全饱和死白区域，只能抑制彩边，无法恢复已经丢失的色彩信息。
6. 标定视图会保留黑电平扣除与坏点修复；想要字面完全原始传感器像素，需要在传感器面板手动关闭坏点修复开关。
7. lensfun 功能依赖外部 CC‑BY‑SA3.0 数据库，数据库缺失则镜头校正不可用。
